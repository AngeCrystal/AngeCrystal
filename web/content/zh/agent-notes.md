## 模型提出下一步之后

让我持续想做 Agent 的，不只是它能回答什么，还有回答之后的那一步：读文件、调用工具、提出修改，再根据执行结果继续。

`/patchpilot` 是我把这些问题写进代码的地方。

### 工具不是一句提示词

我关注工具怎么注册、不同模式能使用哪些能力，以及模型提出的动作如何交给宿主检查和执行。把规则写进程序后，才有机会用测试验证它在失败时做了什么。

### 记住什么，又重新确认什么

我正在梳理长短期记忆的触发、存储和提取，也想分清记忆、RAG 与网络搜索各自解决的问题。

PatchPilot 里的上下文压缩提供了一个具体切口：历史摘要可以帮助继续工作，但不能代替重新读取文件，也不能成为一次操作已经获批或测试已经通过的证明。

### 让结果说得清楚

提出方案、获得批准、写入文件、测试通过，是不同的状态。相比一句“完成了”，我更希望能看清过程停在哪一步，还有什么没有验证。

这些仍是正在推进的实验和学习问题。
