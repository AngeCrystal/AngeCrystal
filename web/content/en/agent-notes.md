## After the model proposes the next step

What keeps me working on agents is what happens after an answer: reading files, calling tools, proposing edits, and continuing from execution feedback.

`/patchpilot` is where I turn those questions into code.

### A tool is more than a prompt

I'm interested in tool registration, capabilities available in different modes, and how a host checks and executes a model's proposed actions. Rules implemented in code can be tested, including when things fail.

### What to remember, what to check again

I'm studying when short- and long-term memory are triggered, how information is stored and retrieved, and how memory differs from RAG and web search.

Context compression in PatchPilot gives me a concrete example: a history summary can help work continue, but it cannot replace reading a file again or prove that an action was approved or a test passed.

### Make the outcome legible

A proposal, an approval, a file write, and a passing test are separate states. Beyond “done,” I want to see where execution stopped and what remains unverified.

These are ongoing experiments and questions I'm still learning about.
