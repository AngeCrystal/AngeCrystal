## Manuals currently open

```text
~/notes/

├── systems/     abstractions · architecture
```

These are directions I'm curious about and want to keep exploring, not a proficiency leaderboard.

### Looking down from the program

What draws me to operating systems and system design is that they hide underneath the tools we use every day: how a program runs, how the parts work together, and where an abstraction finally lands.

### From model to action

AI and agents take the question to the other end: how to use tools, take in feedback, and connect one output to a real task. `/patchpilot` is a small experiment in this direction.

### From code to pixels

`/mini-renderer` starts from basic graphics with C++ / OpenGL. It gives these explorations a very direct kind of feedback: the code I write ends up as pixels on the screen.

Rather than listing a long row of tool names, I'd like to leave behind things you can open, run and keep changing.
