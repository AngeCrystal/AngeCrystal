## The code runs. What comes next?

In recent projects, I'm trying to track two things separately: whether the software has been implemented, and whether I understand it.

The Java learning project records engineering progress separately from study exercises. An endpoint returning a response is one engineering step. Explaining how a request gets there, or what changes when a condition changes, takes practice of my own.

### Keep a task small enough to inspect

PatchPilot adds capabilities in small stages, followed by review, fixes, and another check. This homepage also started with a usable deployment, with content and interaction added gradually.

### Leave a place to resume

I use Markdown for tasks, stage notes, and progress, so returning after a break doesn't mean guessing where I left off.

The terminal follows the same idea: each command opens a small page that can change as I learn.

Two concrete paths are `/patchpilot` and `/stockflow`.
