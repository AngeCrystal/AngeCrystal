## Get one small thing running first

While building this homepage, the rhythm I chose was: **have a usable first version, then add features slowly.**

Write down clearly what I want to say, build a page you can actually use, see where it feels awkward, then keep revising. A terminal with only a few commands, but one that really works, is enough of a starting point.

### Content can grow on its own

Introductions and project notes live in Markdown; command entries live in a config file. Changing a paragraph shouldn't mean rewriting the interface, and adding a page shouldn't turn into a big project.

### Showing can be interactive too

I'd like visitors to choose what they want to learn about, instead of being made to read an introduction from top to bottom. Typing `/help`, opening a project, then wandering off in another direction: that process is itself part of the homepage.

These are the practices used in this project, not a manifesto for every project. When new needs come up, they'll keep changing.
